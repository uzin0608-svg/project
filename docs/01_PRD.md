# PRD — 현장별 공정·기성 대시보드

## 한눈에 보기

- 현장을 총괄하는 임원·팀장이 매달 12개 현장의 공정·기성을 한 화면에서 비교하고, 늦어진 현장과 그 기록을 바로 확인합니다.
- 첫 화면은 점검이 필요한 현장 순위이고, 그 위에 큰 숫자 한 줄이 붙습니다.
- 숫자는 프로그램이 계산합니다. AI는 계산된 숫자와 기록된 상황·대응 계획을 근거로 설명만 합니다.
- 자료는 교육용 가상 자료(현장 A~L 12곳, 2025년 10월~2026년 9월, 144행·15개 열)입니다. 실제 회사 자료가 아닙니다.
- 성공 기준은 이 문서 아래의 "정답 숫자"와 같은 결과가 화면·CSV·AI 답변에 나오는 것입니다.

## 누가·언제·왜 쓰는지

| 구분 | 내용 | 근거 |
|---|---|---|
| 누가 | 현장을 총괄하는 임원·팀장 | 질문 1 답: B |
| 언제 | 매달 새 월말 자료를 가져온 뒤, 현장 현황을 확인할 때 | 자료의 한 행이 "한 현장의 한 달 월말 상태"입니다. |
| 왜 | 계획보다 늦어진 현장을 빨리 찾고, 그 현장에 어떤 상황과 대응이 기록되어 있는지 확인하려고 | 질문 1 답: 임원·팀장은 늦어진 현장을 빨리 파악하는 것이 목적입니다. |

## 줄이고 싶은 불편

| 불편 | 이 화면이 줄이는 방법 | 근거 |
|---|---|---|
| 현장별 엑셀을 하나씩 열어 비교하는 시간 (질문 2 답: A) | 12개 현장을 한 비교표에 모으고, 월·지역·유형·현장 필터로 같은 범위의 숫자·표·차트·CSV·AI를 한꺼번에 바꿉니다. | 자료가 144행이라 현장별로 열어 비교하면 시간이 많이 듭니다. |
| 직접 계산하다 생기는 실수 (이번에 먼저 줄이려는 불편은 아님) | 기성률·공정차이·상태·당월기성액은 프로그램이 계산합니다. | 계산 정확성은 필수 기능에 포함됩니다. |

## 사용자가 고른 내용 (질문 7개)

| # | 질문 | 답 | 화면에 반영되는 방식 |
|---|---|---|---|
| 1 | 이 화면을 주로 누가 쓰나요? | B. 현장을 총괄하는 임원·팀장 | 늦어진 현장을 빨리 파악하는 데 맞춥니다. |
| 2 | 가장 먼저 줄이고 싶은 불편은? | A. 현장별 엑셀을 하나씩 비교하는 시간 | 12개 현장을 한 표와 필터로 묶습니다. |
| 3 | 첫 화면에서 가장 먼저 보여 줄 것은? | A. 점검이 필요한 현장 순위 (위에 큰 숫자 한 줄을 함께) | 첫 화면 순서: 필터 → 큰 숫자 4개 → 점검 순위 → 추이. |
| 4 | 점검 현장 한 줄에 함께 보여 줄 숫자는? | C. 계획·실제 공정률과 기성률 모두 | D라면 `계획 86.5% · 실제 75.8% · 기성률 69.4% · -10.7pp`로 보입니다. |
| 5 | 점검 현장 한 줄을 누르면? | A. 현장별 비교표로 가서 그 현장 줄을 강조하고 기록을 펼침 | D를 누르면 공사기간·기록된 상황·대응 계획이 열립니다. |
| 6 | 내려받은 CSV를 주로 어디에 쓰나요? | B. 엑셀에서 더 계산하기 | 원본 15개 열에 기성률·공정차이·상태·당월기성액 4개 열을 더해 19개 열로 내보냅니다. |
| 7 | AI에게 주로 무엇을 묻게 될까요? | A. 점검 이유와 기록된 대응 설명 | AI에게 묻기 화면의 예시 질문에 반영합니다. |

## 만들 기능 (필수 기능)

| # | 기능 | 사용자가 할 수 있는 일 | 근거 |
|---|---|---|---|
| 1 | 자료 가져오기 | CSV 또는 JSON 파일을 고르면 검사 결과와 미리보기를 보고, 확인 후 전체를 바꿉니다. 오류가 있거나 취소하면 지금 자료를 그대로 둡니다. CSV를 가져온 뒤 같은 JSON을 가져와도 144행입니다(288행으로 쌓이지 않음). | 잘못된 파일 때문에 정상 자료가 사라지면 안 됩니다. |
| 2 | 현황 보기 | 처음에는 2026년 9월·전체 현장을 봅니다. 월·지역·공사 유형·현장을 고릅니다. 전체 기성률, 계획 공정률, 실제 공정률, 공정차이를 큰 숫자 4개로 봅니다. 선택 월까지의 계획·실제 공정률 추이와 월별 기성 막대를 봅니다. | 자료의 기본 조회 기준이 2026-09·전체입니다. |
| 3 | 점검 현장 찾기 | 공정차이가 작은 순(같으면 현장 ID 순)으로 점검 현장 순위를 봅니다. 한 줄에 계획·실제 공정률, 기성률, 공정차이가 함께 나옵니다. 줄을 누르면 비교표로 이동하여 그 현장이 강조되고 기록이 펼쳐집니다. | 질문 3·4·5 답 |
| 4 | 현장별 비교표 | 12개 현장의 지역·유형·당월 주요 공종·금액·공정·상태를 한 표로 봅니다. 행을 펼치면 공사기간·기록된 상황·대응 계획이 같은 페이지 안에서 열립니다. | 질문 2 답: 현장별 엑셀 비교를 한 표로 대신합니다. |
| 5 | CSV 내보내기 | 지금 고른 월·지역·유형·현장과 같은 범위를 내보냅니다. 원본 15개 열에 기성률·공정차이·상태·당월기성액 열을 더하고, 숫자와 단위를 그대로 유지하며, 엑셀에서 한글이 깨지지 않게 합니다. | 질문 6 답 |
| 6 | AI에게 묻기 | 지금 범위를 확인하고 예시 질문을 누르거나 직접 질문을 입력합니다. 답변에는 기준 월·현장·근거 숫자·참고한 기록 필드가 함께 표시됩니다. 월·지역·유형·현장을 바꾸면 이전 답변이 지워집니다. AI 연결이 실패해도 대시보드와 CSV는 계속 씁니다. | 질문 7 답 |

### 큰 숫자 4개 (AI 결정)

| 숫자 | 설명 | 근거 |
|---|---|---|
| 전체 기성률 | 선택 범위의 누적기성액 ÷ 계약금액 × 100 | 실습조건의 현황 보기 항목 |
| 계획 공정률 | 계약금액으로 가중한 평균 | 〃 |
| 실제 공정률 | 계약금액으로 가중한 평균 | 〃 |
| 공정차이 | 실제 − 계획 (pp) | 〃 |

당월기성액은 큰 숫자가 아니라 월별 기성 막대와 현장별 비교표에 보여 줍니다. (AI 결정 — 근거: 실습조건이 큰 숫자로 정한 것은 기성률·계획·실제 공정률·공정차이입니다.)

### 상태 구분 기준

| 상태 | 기준 | 표시 (AI 결정) |
|---|---|---|
| 정상 | 공정차이 0pp 이상 | 색 + "정상" 글자 |
| 주의 | −5pp 초과, 0pp 미만 | 색 + "주의" 글자 |
| 점검 | −5pp 이하 | 색 + "점검" 글자 |

근거: 색만으로는 구별이 어려울 수 있어 글자를 함께 씁니다. 상태는 공정차이로만 판정하고, 자료의 `issueCategory`(특이사항 분류)는 상태 판정에 쓰지 않습니다.

### 자료를 다룰 때 지킬 점

| 항목 | 내용 | 근거 |
|---|---|---|
| 첫 달 당월기성액 | 2025-10은 전월 자료가 없어 "계산 불가"로 표시합니다. 누적액을 당월액으로 대신하지 않습니다. | 당월기성액 = 이번 달 누적 − 바로 전달 누적 |
| 0.0은 정상값 | J의 7월 당월기성액 0.0은 누락이 아닙니다. 기록에 "기성 확인 서류 보완"이 있습니다. | 누락과 0을 구별해야 합니다. |
| 기성률과 공정률은 다른 값 | 기성률은 금액 기준, 공정률은 공정 기준이라 같지 않을 수 있습니다. | 데이터 설명서 |
| 자료 없음 | 0%로 바꾸지 않고 "자료 없음·계산 불가"로 보여 줍니다. | 0%는 실제 값처럼 읽힙니다. |
| 기록의 성격 | 기록된 상황은 "기록된 상황", 대응 계획은 "계획된 대응"으로 보여 줍니다. 원인 확정이나 완료 사실로 바꾸지 않습니다. | 데이터 설명서 |
| 가상 자료 | 모든 현장명에 [가상]이 붙습니다. 실제 회사의 계약·현장으로 소개하지 않습니다. | 교육용 가상 자료입니다. |

## 만들지 않는 것

| 만들지 않는 것 | 이유 |
|---|---|
| 로그인 | 이번 실습 범위 밖입니다. |
| 데이터베이스 | 파일을 브라우저에서 읽고 계산합니다. 서버에 저장하지 않습니다. |
| 회사 시스템 연동 | 가상 자료 파일만 사용합니다. |
| 실제 기성 청구·발주 | 조회·분석 화면이며 업무 처리 화면이 아닙니다. |
| 일정 예측 | 계약상 준공일은 예정일일 뿐 실제 완료 예측이 아닙니다. |
| 새로고침 후 자료 유지 | 새로고침하면 파일을 다시 가져옵니다. |
| 수금액·미수금 | 자료에 청구액·수금액·미수금이 없습니다. |
| 현장 상세 별도 페이지 | 비교표의 펼침 행이 같은 페이지 안에서 상세를 보여 줍니다. |
| 원본에 없는 값을 자료에 저장 | 기성률·공정차이·상태는 프로그램이 계산하며 원본에 중복 저장하지 않습니다. |

## 성공 기준

질문하지 않고 `실습조건.md`의 정답 숫자와 같은 결과가 나오는 것을 기준으로 합니다.

| 확인할 것 | 정답 |
|---|---|
| 9월 전체 | 계약금액 630,700 · 누적기성액 424,063.4(백만원) · 기성률 67.2% |
| 9월 공정률 | 계획 73.2% · 실제 71.2% · 공정차이 -2.0pp |
| 9월 당월기성액 | 28,878.7백만원 |
| 8월 전체 | 누적기성액 395,184.7 · 기성률 62.7% |
| 7월 전체 | 누적기성액 364,718.5 · 기성률 57.8% |
| 9월 점검 순서 | D(-10.7pp) → I(-7.6pp) → K(-5.4pp) |
| 9월 상태 내역 | 정상 6곳 · 주의 3곳 · 점검 3곳 |
| 9월 D | 기성률 69.4%, D만 CSV로 내보내면 데이터 1행 |
| 9월 인천·공동주택 | A·G 2곳, 내보내기 데이터 2행 |
| 2025-10 | 당월기성액 계산 불가, 누적액을 당월액으로 대신하지 않음 |
| J의 7월 | 당월기성액 0.0, 기록상 기성 확인 서류 보완 |
| 오류 파일 3종 | 모두 거부, 지금 자료 유지 |
| 'D가 늦어진 원인과 대응은?' | 공급 정상화 후에도 남은 지연과 주간 확인 계획을 기록대로 설명 |
| '실제 준공일·미수금은?' | 자료 없음, 계약상 준공일과 실제 완료일을 구분 |

단위·계산·검증 기준은 `data/데이터설명.md`와 `data/검산표.md`를 따릅니다.
